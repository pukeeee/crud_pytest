# CRUD Сервіс для Користувачів

Цей репозиторій містить сучасний бекенд-сервіс для управління користувачами, створений з використанням **FastAPI**, **SQLAlchemy** та **PostgreSQL**.
Він демонструє чисту архітектуру, надійну валідацію, JWT-аутентифікацію та повний набір юніт- та інтеграційних тестів.

---

## 🗂️ Структура Проекту
```
crudPytest/
│
├── src/

│ ├── controller/ # Маршрути FastAPI (рівень API)

│ ├── dto/ # Схеми Pydantic та валідація
│ ├── service/ # Бізнес-логіка та класи помилок

│ ├── integration/ # Інтеграційні тести (API + БД)
│ ├── unit/ # Юніт-тести (сервіс, валідація, репозиторій)
│
├── docker-compose.yml
├── dockerfile
├── requirements.txt
├── pytest.ini
└── README.md
```

## 🧩 Основна Логіка

- **Рівень API** (`src/controller/user_controller.py`):
  Обробляє HTTP-запити, впровадження залежностей та відображення помилок.
- **Рівень Сервісу** (`src/service/user_service.py`):
  Містить бізнес-логіку, валідацію та керує викликами до репозиторію.
- **Рівень Репозиторію** (`src/db/db_repository.py`):
  Безпосередньо взаємодіє з базою даних за допомогою SQLAlchemy ORM.
- **DTOs** (`src/dto/`):
  Моделі Pydantic для валідації та серіалізації запитів/відповідей.
- **Аутентифікація** (`src/auth/`):
  Генерація/перевірка токенів JWT та хешування паролів.

## 🧪 Тестування

- **Юніт-тести**:
  - Тестують бізнес-логіку, валідацію та репозиторій в ізоляції.
  - Знаходяться в `tests/unit/`.
- **Інтеграційні тести**:
  - Тестують повний стек API з реальною базою даних (PostgreSQL).
  - Знаходяться в `tests/integration/`.
- **Як запустити тести**:
  - Усі тести можна запустити за допомогою Docker Compose (див. нижче).
  - Ви також можете запускати тести локально, якщо у вас запущено PostgreSQL.

## 🔄 CI/CD

Цей проект використовує [GitHub Actions](.github/workflows/ci-cd.yml) для безперервної інтеграції (Continuous Integration).

Воркфлоу автоматично запускається на кожен `push` або `pull_request` до гілки `master` і виконує наступні кроки:
- **Налаштовує середовище Python.**
- **Встановлює всі залежності.**
- **Запускає повний набір тестів** (юніт та інтеграційні) на чистій базі даних PostgreSQL.
- **Надсилає сповіщення в Telegram** у разі провалу тестів або успішного злиття pull request.
- **Автоматично зливає pull request'и** з міткою `automerge`, якщо всі тести пройшли успішно.

## 🐳 Запуск за допомогою Docker Compose

**Вимоги:**
- [Docker](https://www.docker.com/) та [Docker Compose](https://docs.docker.com/compose/)

**Запустити всі сервіси та виконати тести:**
```bash
docker-compose up --build --abort-on-container-exit
```
- Ця команда створює Docker-образ, запускає базу даних PostgreSQL та виконує повний набір тестів в ізольованому середовищі.
- Після завершення тестів усі контейнери будуть автоматично зупинені.

**Запуск бази даних для локальної розробки:**
Якщо ви хочете запустити лише базу даних і підключитися до неї з локальної машини (наприклад, для ручного тестування або запуску `pytest` локально), використовуйте:
```bash
docker-compose up postgres
```
База даних PostgreSQL буде доступна на `localhost:5445`.

## ⚙️ Змінні Середовища

Вся конфігурація керується через файл `.env` у корені проекту.

**База даних:**
- `POSTGRES_USER`: Ім'я користувача бази даних.
- `POSTGRES_PASSWORD`: Пароль користувача бази даних.
- `POSTGRES_DB`: Назва бази даних.
- `POSTGRES_HOST`: Ім'я хоста для сервісу бази даних (використовується всередині Docker).
- `POSTGRES_PORT`: Порт для сервісу бази даних (використовується всередині Docker).

**Аутентифікація:**
- `SECRET_KEY`: Секретний ключ для підпису токенів JWT.
- `ALGORITHM`: Алгоритм, що використовується для підпису JWT (наприклад, `HS256`).
- `ACCESS_TOKEN_EXPIRE_MINUTES`: Час життя токена доступу в хвилинах.
